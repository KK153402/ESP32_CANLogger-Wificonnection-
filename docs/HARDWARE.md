# CANログ取得治具 ハードウェア仕様 Rev.5（基板設計着手版）

対象ファームウェア: `CanLoggerJig` v2.5
動作仕様・スループット試算は [`DESIGN.md`](DESIGN.md)、
プログラムの中身の解説は [`TECHNICAL.md`](TECHNICAL.md) を参照。

Rev.5 で反映した内容
- **RTC を MCP7940N-I/SN へ変更**（外部32.768kHz水晶が必要。§11）

Rev.4 で反映した内容
- ヒューズを **MF-FSML100/8-2** に確定（0603 / 耐圧8VDC）
- USB D+/D- に **TPD2E2U06DCKR**（ESD保護）を追加
- CMC バイパス用の **0Ω ジャンパを部品化**（DNP時の断線を防止）
- 絶縁2次側のネット名を `GND2_CH1` / `GND2_CH2` へ改名
- 未使用ピンにテストポイントを配置
- R / C の定数表（§4）を追加

> **ピン番号について** — ICは**信号名で記載**している。ピン番号は各ICのデータシートで照合すること。
> ESP32側のGPIO番号はファームウェアの `src/config.h` と一対一で対応しており、
> 変更する場合は `config.h` も合わせて修正する必要がある。

## 1. 部品確定の経緯

| 部品 | 検討過程 | 確定 |
|---|---|---|
| CANトランシーバ | ISO1050DWRは電源断後の再初期化遅延対策（VCC2ブリード抵抗）が必要。バス障害保護も±27/40Vと低い | **ISO1042DWV** |
| TVS（CAN） | PEC3824C2Aは最小発注3,000個。TSD12Cはスタンドオフ12VでISO1042のコモンモード±30Vに対し低すぎ | **RESD1CANY**（24V双方向・2ライン1パッケージ） |
| 絶縁DC/DC | MAU106は+5V/-5Vデュアルで用途違い。MAU102は絶縁1kVDCだが同じく非安定化 | **NME1S0505SC**（1kVDC機能絶縁・**要ダミー負荷**） |
| 降圧コンバータ | RT8250GSPはVin=5V・デューティ66%の両方が外部ブートストラップダイオード追加条件に該当 | **TPS562201DDCR**（内部補償・ダイオード不要） |
| インダクタ | データシートTable 7-2 より、3.3V出力時はMIN/TYPとも3.3µH（2.2µHは1.8V以下の値） | **DFE322520FD-3R3M=P2**（3.3µH / Isat 4.2A / DCR 65mΩ） |
| ヒューズ | 0.5A品＋直列ショットキーではVINが4.5Vを割る。1A品へ変更しショットキーを廃止 | **MF-FSML100/8-2**（0603 / 1A / 40mΩ / 耐圧8VDC） |
| USB-UART | FT231XSが入手難。CH340Gは12MHz水晶が必要 | **CH340E**（内蔵クロック・水晶不要。**DTR#なし→手動書き込み**） |
| ESD保護（USB） | 現地ではPC非接続だが、書き込み作業時の保護として追加 | **TPD2E2U06DCKR**（1.5pF / ±25kV接触） |
| RTC | DS1302は温度補償なし・独自3線式。DS3231MZは高価。DS1307は**VCC 4.5〜5.5Vの5V専用**で3.3V系では使用不可 | **MCP7940N-I/SN**（1.8〜5.5V・I2C 0x6F・SOIC-8・**外部水晶必要**） |
| CANコントローラ | — | **MCP2515T-I/SO**（SOIC-18） |
| CMC | Listen-Onlyでバスを駆動しないため放射ノイズ源にならない | **DNP**（0Ωジャンパで短絡。ジャンパは部品化済み） |

**絶縁の位置づけ**: 接続先は制御系CANで高電圧系ではないため、安全絶縁ではなく
**グランドループ遮断を目的とした機能絶縁**とする。NME1S0505SCはULから機能絶縁として
認定されており、入出力ともSELV限度（60VDC未満）内で使う前提の部品である。
**安全絶縁システムの要素として使ってはならない**ため、高電圧が乗り得るバスには接続しないことを
作業手順書と治具のラベルに明記する。

## 2. ブロック構成

```
                    ┌──── 機能絶縁境界（CH1）──────┐
CN1 (CAN1 500k) ────┤ RESD1CANY → [CMC:DNP / 0Ω]   │
  H / L            │        → ISO1042DWV          ├─── ESP32 内蔵TWAI (GPIO21/22)
                   │  NME1S0505SC + 100Ωダミー     │
                   │  VCC2_CH1 / GND2_CH1          │
                   └───────────────────────────────┘

                    ┌──── 機能絶縁境界（CH2）──────┐
CN2 (CAN2 250k) ────┤ RESD1CANY → [CMC:DNP / 0Ω]   │
  H / L            │        → ISO1042DWV          ├─── MCP2515 ── HSPI (13/14/35/4)
                   │  NME1S0505SC + 100Ωダミー     │    16MHz XTAL  INT(34) RESET(26)
                   │  VCC2_CH2 / GND2_CH2          │
                   └───────────────────────────────┘

USB-C ─ TPD2E2U06 ─ MF-FSML100 ─ 5V ─ TPS562201 ─ 3.3V ─ ESP32-WROOM-32E-N16
        (D+/D-)                                          ├── microSD (VSPI: 18/19/23/5)
                                                         ├── MCP7940N (I2C: 16/17) + 32.768kHz + CR2032
                                                         ├── 開始SW(32) / 停止SW(33)
                                                         ├── 状態LED(25)
                                                         ├── BOOTSW(IO0) / ENSW(EN)
                                                         └── CH340E ── UART0 (1/3)
```

**CH1とCH2の絶縁アイランドは完全に分離する。**
`VCC2_CH1` / `GND2_CH1` / `VCC2_CH2` / `GND2_CH2` の4ネットが独立していること。

> **ネット名について**: ISO1042のピン名では `GND1` がロジック側、`GND2` が絶縁側を指す。
> ネット名を `GND1` / `GND2` にすると「U2のGND2ピンがネットGND1に載る」という
> 取り違えを誘うため、**`GND2_CH1` / `GND2_CH2`** に改名している。

## 5. SDカードまわりの注意

### プルアップ

| 信号 | Ref | 目的 |
|---|---|---|
| DAT1 (pin8) | R9 | 未使用DATラインをHighに固定 |
| DAT2 (pin1) | R10 | 同上 |
| DAT3 / CS (pin2) | **R22** | GPIO5はストラッピングピン。カード未挿入時のフローティング防止 |
| DAT0 / MISO (pin7) | **R23** | カードがHi-Zの間のフローティング防止 |

### デカップリング

**ソケット直近に10µF + 100nF が必須。** SDカードは書き込み時に大きな電流スパイクを出し、
電圧が落ちるとカードがハングする。基板上で最も優先度の高いデカップリングのひとつ。

## 6. 絶縁電源とダミー負荷（最重要）

### 6.1 なぜダミー負荷が必要か

NME1S0505SCは**非安定化（unregulated）**タイプで、データシートに次の記載がある。

> データシート仕様を満たす最小負荷は定格負荷の10%。10%を下回ると出力電圧が上昇し、
> 負荷が5%未満に落ちると**典型的に規定出力電圧の2倍まで上昇し得る**。

この治具はListen-Onlyで**一切送信しない**ため、ISO1042のバス側電流は受信状態の
**約5〜10mA**しか流れない。200mA定格に対して**2.5〜5%負荷**であり、
出力が最も跳ね上がる領域に常時居続けることになる。

出力が10V付近まで上昇するとISO1042のVCC2絶対最大定格を超え、**トランシーバが破損する**。

### 6.2 抵抗値の選定

| 抵抗値 | 電流 | 負荷率 | 想定出力電圧 | ch当たり消費 | 判定 |
|---|---|---|---|---|---|
| なし | — | 2.5〜5% | 最大約10V | — | **破損** |
| 220Ω | 22.7mA | 約11% | 約5.5V | 0.12W | 上限ぎりぎり |
| **100Ω** | **50mA** | **約25%** | **約5.2V** | **0.27W** | **推奨** |
| 68Ω | 73.5mA | 約37% | 約5.1V | 0.40W | 上振れした場合の代替 |

**100Ω / 1/2W（1206）を各chのVCC2 - GND2間に実装する。**
トランシーバの約8mAと合わせて約29%負荷になり、ISO1042の推奨VCC2範囲（4.5〜5.5V）に収まる。

> **試作機で必ず実測すること。** 電源投入後、無通信状態で
> **VCC2_CH1 / VCC2_CH2 の電圧を測定**し、**4.5〜5.5Vに入っていることを確認**する。
> 上振れしていれば68Ωへ下げる。テストポイントを2ヶ所に出しておくこと。

### 6.3 絶縁境界の扱い

- NME1S0505SCの絶縁は**1kVDC（1秒）の機能絶縁**。安全絶縁ではない
- 入出力とも**SELV限度（60VDC未満）内**で使用する前提
- **`VCC2_CH1`/`GND2_CH1` と `VCC2_CH2`/`GND2_CH2` は絶対に接続しない**

## 7. ISO1042DWV の接続（各chに1個）

データシート照合済み（DWV: 1=VCC1, 2=TXD, 3=RXD, 4=GND1, 5=GND2, 6=CANL, 7=CANH, 8=VCC2）。

| ISO1042 信号 | 接続先 | 備考 |
|---|---|---|
| VCC1 | 3.3V（ロジック側） | 100nFを直近に |
| GND1 | ロジック側GND（ネット名 `GND`） | |
| TXD | CH1: ESP32 GPIO21 / CH2: MCP2515 TXCAN | **10kΩでVCC1へプルアップ** |
| RXD | CH1: ESP32 GPIO22 / CH2: MCP2515 RXCAN | |
| VCC2 | NME1S0505SC 出力（`VCC2_CH1` / `VCC2_CH2`） | 4.7µF + 100nF。**ダミー負荷100Ω併設** |
| GND2 | 絶縁側GND（`GND2_CH1` / `GND2_CH2`） | |
| CANH | CN 1番ピン | 経路上にTVS → CMC/ジャンパ |
| CANL | CN 2番ピン | 同上 |

**TXDプルアップが必要な理由**: ISO1042のTXDは内部で非常に弱くVCC1へプルアップされている
だけである。制御側がフロートするとバスに問題を起こす可能性があるため、外部プルアップで
レセッシブに固定する。**CH1はESP32起動前、CH2はMCP2515リセット中**にこの状態になる。

### 終端抵抗は実装しない

測定対象側で終端されているため、**治具側に120Ωを実装してはいけない**。

## 8. TVS と コモンモードチョーク

### 配置順

```
コネクタ → RESD1CANY → [CMC(DNP) ∥ 0Ωジャンパ] → ISO1042
```

**TVSは必ずコネクタ直後**に置く。TVSからGNDへの経路は最短・低インダクタンスにする。
TVSのGND端子は**そのchの絶縁側GND**（`GND2_CH1` / `GND2_CH2`）へ落とすこと。

### RESD1CANY

- VRWM 24V / PPP 350W / SOT-23 / 2ライン1パッケージ
- **1パッケージ2ラインなので個別TVS2個のときの容量ミスマッチが起きない**
- **発注前確認**: クランプ電圧VCが**ISO1042のバス障害保護±70V以内**に収まっていること

### CMC は DNP、0Ωジャンパで通す

Listen-Onlyでバスを駆動しないため放射ノイズ源にならず、通常は不要。
ただし**CMCを単に未実装にするとCANラインが断線する**ため、
各chに**0Ω抵抗2本（RJ1〜RJ4, 0603）をCMCの各巻線と並列に配置し、これを実装する**。
CMC（FL2/FL3）側はDNP指定。

将来CMCが必要になった場合は、0Ωジャンパを外してCMCを実装する。

> **ACT45Bの巻線ペアを必ず照合すること。** ネットリストは 4↔1 / 3↔2 が
> ストレートに導通する前提で配線している。KiCadシンボルの内部結線が 1↔2 / 3↔4 だと
> **CANH/CANLがクロスまたは短絡する**。0Ωジャンパも同じペアで置くこと。

## 9. CANコネクタと誤挿入対策

**相手側（測定対象側）のコネクタが両chとも B02B-XASK-A のため、治具側だけ変更できない。**
以下の運用対策で誤挿入を検出する。

| 対策 | 内容 |
|---|---|
| ケーブル識別 | ケーブルに色分け＋タグ（「CH1 500k」「CH2 250k」）を付ける |
| 基板シルク | CN1/CN2 の脇に `CH1 500kbps` / `CH2 250kbps` を印字 |
| **検出手順** | 統計ファイルで**両chとも `frames logged` が0でないこと**を確認する |

Listen-Onlyのためビットレートを間違えても**エラーが出ず0件で終わる**。
片方だけ0件なら挿し間違いか未接続と判断できるので、**この確認手順を省略しないこと**。

**CAN_GND端子が無い点**は残課題。GND2が完全に浮くためコモンモード電位の基準が
定まらないが、絶縁トランシーバなので差動としては動作する。
実機で通信が不安定な場合は、GND2に高抵抗（1MΩ程度）で基準を与えることを検討する。

**ハーネス製作時の照合**: J2/J3 の **1番ピン=CANH / 2番ピン=CANL** を前提に
TVS・CMC・トランシーバが配線されている。測定対象側ハーネスのピン割当と一致するか確認すること。

## 10. USB-UART（CH340E）と書き込み方法

### 手動書き込みになる

CH340Eは6番ピンがTNOWで、**DTR#を持たない**。ESP32の自動リセットにはDTR#とRTS#の
両方が必要なため、**手動書き込みとなる**。

この治具はファーム書き込み頻度が極めて低いため、自動リセット回路を省く判断は妥当。

**手順**: BOOTボタンを押しながらENボタンを押して離す → BOOTを離す → 書き込み

**基板シルクに手順を印字しておくこと。**

### 電源接続

| ピン | 接続 |
|---|---|
| VCC | **3.3V** |
| **V3** | **3.3V（VCCと同じネット）** ＋ 100nF |

CH340は3.3V駆動時にV3をVCCへ接続する。5V駆動にするとTXDが5Vで出てESP32が壊れる。
内蔵クロック生成器を持つため**外部水晶は不要**。

### ESD保護（TPD2E2U06DCKR）

D+/D- に2チャネルのESD保護を入れる。ライン容量1.5pFはUSB 2.0 Full Speed（12Mbps）に対し
十分に低く、信号品質への影響はない。

**配置が重要**: **USBコネクタのピンから5mm以内**、D+/D-上の他の部品より手前に置く。
離れた位置に置くと、サージがESD素子に到達する前に他の回路へ回り込むため効果が落ちる。

## 11. RTC（MCP7940N-I/SN）

### 11.1 役割

**記録開始時の実時刻を、BINヘッダの `unix_time` フィールド（+20、UTC）に書き込む。**

| できること | できないこと |
|---|---|
| 測定対象のイベントログとの時刻照合 | CANalyzerでの再生（相対タイムスタンプで動作するため無関係） |
| 目撃報告（「14時ごろ止まった」）との突合 | フレーム個々のタイムスタンプ精度の改善 |
| 複数ログ（LOG0001/0002…）の順序と間隔の把握 | フレーム間隔の測定精度（esp_timerが担当） |

必要精度は秒〜分オーダー。RTCは「t=0が実世界の何時何分か」というアンカーを与えるだけなので、
温度補償なし（外部水晶）のMCP7940Nで十分。

### 11.2 水晶と負荷容量（最も外しやすい点）

MCP7940Nのデータシート冒頭に、オシレータの仕様として次の記載がある。

> Oscillator for 32.768 kHz Crystals: **Optimized for 6-9 pF crystals**

**CL = 6〜9pF の水晶を使うこと。** MCP7940系のオシレータは低消費設計でドライブ能力が
小さく、高CL品では発振余裕が減る。推奨水晶リストには10pF/12pF品も載っているが、
上記のヘッドライン仕様を優先する。

負荷容量はデータシートの式から逆算する。

```
CL = (CX1 × CX2)/(CX1 + CX2) + Cstray
     ※ CX1 = 外付け容量 + COSC(3pF)、CX1 = CX2 とする
     CX1 = CX2 なら CL = CX/2 + Cstray
```

**外付け容量から実効CLを逆引きした表**（COSC = 3pF）

| 外付け | Cstray=2pF | Cstray=3pF | Cstray=5pF |
|---|---|---|---|
| **6pF** | 6.5 | **7.5** | 9.5 |
| **7pF** | 7.0 | **8.0** | 10.0 |
| **8pF** | 7.5 | **8.5** | 10.5 |
| 15pF | 11.0 | 12.0 | 14.0 |
| 18pF | 12.5 | 13.5 | 15.5 |

**CL = 6〜7pF の水晶に対して外付け 6〜8pF** が正しい組み合わせ。
C0G/NP0を使うこと（X7Rでは温度で容量が変わり周波数がずれる）。

#### 試作1号機（FC-135 / CL=12.5pF + 外付け7pF）の評価

**発振は正常にしている**（`SETTIME` → `OSCRUN=1` を実機で確認済み）。
実効CLは約8pFで、これはMCP7940Nの最適範囲6〜9pFに収まっているため、
発振余裕の面では問題ない。

問題は**周波数精度**。水晶の仕様CL(12.5pF)より実効CL(8pF)が小さいため、
発振周波数が高くなり**時計が進む**。

| C1 | C0 | 誤差 | 秒/日 | 分/年 |
|---|---|---|---|---|
| 1.6 fF | 1.35 pF | +27.8 ppm | +2.4 s | +14.6 分 |
| 1.8 fF | 1.35 pF | +31.3 ppm | +2.7 s | +16.4 分 |
| 2.2 fF | 1.35 pF | +38.2 ppm | +3.3 s | +20.1 分 |

**負荷容量を15〜18pFへ増やしてはいけない。** 実効CLを12.5pFに合わせられるが、
発振余裕を削る方向であり、MCP7940Nの最適範囲(6〜9pF)からも外れる。

**対処は2つ。**

| 方法 | 内容 |
|---|---|
| **A. デジタルトリミングで補正**（1号機向け） | ハード改修不要。§11.6参照。±129ppmの補正範囲があり、+30ppm程度は余裕で吸収できる |
| **B. 次版でCL=6〜7pF品へ変更**（推奨） | 外付けは6〜8pFのまま。精度と発振余裕の両方が正しくなる |

#### 発振しない場合の切り分け順序

MCP7940Nは**工場出荷時 ST=0 で発振していない**のが正常。
`SETTIME` を打つまでは `OSCRUN=0` のままなので、これを故障と誤認しないこと。

1. `SETTIME` を実行する
2. `[OK]` が返れば発振している（完了）
3. `oscillator did not start within 5 s.` が出た場合のみ、以下を疑う
   - 水晶のCL指定と負荷容量の不整合
   - **水晶周辺のフラックス残渣**（32kHz水晶は残渣だけで発振が止まる）
   - 水晶の実装不良

データシートにレイアウト推奨図（Figure 5-3）があるので、それに従うこと。

- 水晶は**IC直近**、配線最短
- 周囲をガードGNDで囲む
- TPS562201のインダクタやCANラインから離す

発振が立ち上がらない場合、ファームウェアが起動時に
`[WARN] MCP7940N: oscillator not running. check crystal / load caps.` を出す。

### 11.3 接続

| MCP7940N 信号 | 接続先 | 備考 |
|---|---|---|
| VCC | 3.3V | 100nFを直近に |
| VSS | GND | |
| SDA / SCL | ESP32 GPIO16 / GPIO17 | 4.7kΩでプルアップ（R14/R15） |
| X1 / X2 | 32.768kHz水晶 + 負荷容量×2 | §11.2 |
| VBAT | CR2032（+） | 直列ダイオード・抵抗を入れないこと |
| MFP | 未接続 | 使う場合はオープンドレインなので10kΩプルアップが必要 |

I2Cアドレスは **0x6F**（DS3231の0x68とは別）。

### 11.4 ファームウェア側で必須の初期化

MCP7940Nは**電源を入れただけでは時計が動かない**。以下は `src/mcp7940.h` で実装済み。

| 項目 | レジスタ | 内容 |
|---|---|---|
| 発振器の起動 | RTCSEC bit7 = **ST** | 1を書かないと発振しない |
| バックアップ有効化 | RTCWKDAY bit3 = **VBATEN** | **デフォルト無効**。忘れると電源断で時刻が消える |
| 発振確認 | RTCWKDAY bit5 = OSCRUN | 実際に回っているかの確認に使う |
| 電源断履歴 | RTCWKDAY bit4 = PWRFAIL | 起動時ログに表示する |

### 11.5 時刻の設定

RTCには**現地時刻（日本時間）**を設定する。ファームウェアがUTCへ変換して
`unix_time` に格納するため、PC側で正しい時刻が表示される。

```
pio device monitor
> SETTIME 2026-08-09 14:05:00
[OK] RTC set to 2026-08-09 14:05:00 (local)
```

**製作時に一度設定すれば、CR2032が切れるまで保持される。**
RTCが無い／時刻未設定の場合は `unix_time = 0` となり、記録自体は続行される。

### 11.6 デジタルトリミング（周波数誤差の補正）

MCP7940Nは水晶の周波数誤差をソフトで補正できる。

| 項目 | 値 |
|---|---|
| 補正範囲 | **±129 ppm** |
| 分解能 | **1.017 ppm / step**（TRIMVAL 1あたり） |
| 動作 | CRSTRIM=0 のとき1分ごとに 2×TRIMVAL クロックを加減算 |
| バックアップ動作中 | **補正が効く** |

レジスタは OSCTRIM（0x08）。bit7 = SIGN、bit6:0 = TRIMVAL。

#### 校正手順

1. `SETTIME` で正確な時刻に合わせる（電波時計やPCの時刻を基準にする）
2. **1日以上放置**する（長いほど精度が上がる）
3. `GETTIME` で基準時刻とのずれを測る
4. ppm を計算する： `ppm = 進んだ秒数 ÷ 経過秒数 × 1e6`
5. `TRIM` コマンドで補正値を書く： `step = -ppm ÷ 1.017`
   **時計が進んでいるなら負の値**

```
> TRIM -34          ← 1日3秒進む場合（34.7ppm）
[OK] trim = -34 (-34.6 ppm)
> STATUS
rtc flags: OSCRUN=1 PWRFAIL=0 VBATEN=1 (RTCWKDAY=0x29)  trim=-34 (-34.6 ppm)
```

引数なしで `TRIM` を打つと現在値と使い方が表示される。

> **符号の向きは実測で必ず確認すること。** 補正後にもう一度1日放置して、
> ずれが減っているかを確認する。逆方向に増えていたら符号を反転させる。

補正値はVBAT保持されるので、製作時に一度校正すれば以後は不要。
**個体ごとに水晶の誤差が異なるため、量産時は1台ずつ校正する必要がある。**

## 12. MCP2515 の接続

データシート照合済み（SOIC-18: TXCAN=1, RXCAN=2, OSC2=7, OSC1=8, VSS=9, /INT=12,
SCK=13, SI=14, SO=15, /CS=16, /RESET=17, VDD=18）。

| MCP2515 信号 | 接続先 | 備考 |
|---|---|---|
| VDD | **3.3V** | 100nFを直近。5Vではない |
| OSC1 / OSC2 | 16MHz水晶 + 22pF×2 | **IC直近**。配線最短 |
| SCK / SI / SO | ESP32 GPIO14 / 13 / **35** | SOをGPIO12にしてはいけない |
| /CS | ESP32 GPIO4 | |
| /INT | ESP32 GPIO34 | 10kΩで3.3Vへ |
| /RESET | ESP32 GPIO26 ＋ 10kΩで3.3Vへ | FWからハードウェアリセットを行う |
| TXCAN / RXCAN | CH2 ISO1042 TXD / RXD | |
| /TX0RTS, /TX1RTS, /TX2RTS | 10kΩで3.3Vへ | 送信は使わないが入力ピンなので固定 |
| /RX0BF, /RX1BF, CLKOUT/SOF | 未接続 | |

### ビットタイミング（サンプルポイント）

3レート共通で **16TQ・サンプルポイント87.5%**（CiA推奨）に揃えている。

| ビットレート | CNF1 | CNF2 | CNF3 | 構成 | SP |
|---|---|---|---|---|---|
| 500 kbps | 0x00 | 0xB5 | 0x81 | Sync1 + Prop6 + PS1 7 + PS2 2 = 16TQ | 87.5% |
| 250 kbps | 0x01 | 0xB5 | 0x81 | 同上（TQ=250ns） | 87.5% |
| 125 kbps | 0x03 | 0xB5 | 0x81 | 同上（TQ=500ns） | 87.5% |

autowp系ライブラリの一般的な定数表（500k = 0x00/0xF0/0x86 など）は
サンプルポイントが 9/16 = **56.25%** と低く、バスの立ち上がりリンギングに弱い。

250kbpsは SJW を 2TQ ではなく **1TQ**（CNF1 = 0x01）にしている。
PS2 = 2TQ に対して SJW = 2TQ だと `PhaseSeg2 > SJW` を満たさないため。

## 16. 基板レイアウトの注意

### 15.1 絶縁境界

- ISO1042とNME1S0505SCの下を**銅箔・ベタGNDが横断しないこと**。内層を含め全層で切る
- **CH1とCH2の絶縁側は独立した2つの島**にする
- 機能絶縁なので安全規格上の沿面距離要求は無いが、
  **パッケージのピン間距離より狭いパターンは引かない**

### 15.2 その他

- **TVSはコネクタ直後**。GNDへの経路を最短に
- **TPD2E2U06はUSBコネクタから5mm以内**。D+/D-上の他の部品より手前
- **水晶はMCP2515の直近**。ガードパターンで囲み、TPS562201のインダクタから離す
- **RTC用32.768kHz水晶もMCP7940Nの直近**。同様にガードGNDで囲む（§11.2）
- **SDソケット直近に10µF + 100nF**
- **MCP2515のHSPIとSDのVSPIは物理的に分離**した配線にする
- **VCC2のバイパスコンデンサはトップ層**に置き、ビアを使わずVCC2/GND2ピンへ接続する
- TPS562201のスイッチングノード（SW）は面積を最小に
- **ヒューズ（0603）周囲は放熱を考慮**。トリップ時に約0.5W消費する
- ESP32-WROOM-32Eのアンテナ部は基板端に出しベタを抜く
- **状態LEDと2つの操作ボタンは筐体外から操作/視認できる位置**に配置
